# Device acceptance — not yet executed

Build and unit tests validate implementation, not delivery on a physical S21. Record date, model, OS/One UI version, build name/code and each result before calling the alarm acceptance checks passed.

1. Install debug APK. Open once; grant exact alarms, notifications and full-screen access where present. Exclude battery optimisation, set battery use Unrestricted and add P.A. to Samsung Never sleeping apps. Check alarm volume and alarm notification channel.
2. Press **Test alarm in 20 seconds**, leave the app, remove it from recents and lock the screen. Expect a full-screen alert or an allowed heads-up alert, sound and vibration. Tap Done: sound stops and a completion time appears in the recent history. Wait past the retry deadline: no repeat.
3. Repeat the alarm test; Snooze. Expect no sound during the five-minute snooze, then another alarm. Leave that alert unanswered: expect a retry after ten minutes, then every five. Dismiss terminates retries without logging Done. Swiping away a reminder notification also dismisses that occurrence.
4. Test notification style: a high-priority notification appears without alarm-style looping sound or repeated retries. Done/Snooze/Dismiss operate on that one item. Fire two tests close together and confirm actions on one cannot complete the other.
5. Schedule a test/enable checks, reboot before delivery, then unlock once and lock again. Verify the next queued reminder fires. Repeat with P.A. closed during an app update. Previously Done reminders must stay Done.
6. On an emulator or spare test device, use `adb shell dumpsys deviceidle force-idle`; verify an alarm-clock alert can wake the device. Restore normal operation using `adb shell dumpsys deviceidle unforce`. Do not confuse removal from recents with Android Force stop: Force stop suppresses alarms until the app is opened again.
7. Change the device timezone to an overseas zone. P.A. must keep 09:45–16:00 **London** schedules, not reinterpret them as device-local clock times. Change wall clock, then verify the next alarm is recalculated and no Done check resurrects.
8. In an emulator with auto-time disabled, test October 2026 and March 2027. Rota: Wed/Thu/Fri on; 24–25 October off; 31 October/1 November on. Observe 09:45 BST before the October change and 09:45 GMT after; spring daily time resolution must switch to BST. For an actual alert during the 01:00 overlap/gap, use a test rota anchor/date and custom 01:30 check, then restore production settings. Expect one autumn occurrence and the spring time shifted forward by one hour.
9. Revoke exact alarm, notifications and full-screen access individually. Reopen P.A.: correct missing access must be displayed. Regrant exact-alarm access: queued reminders resume. Denied full-screen access should leave the actionable notification fallback. Test disabling the alarm channel and muting alarm volume so the operating limitations are understood.
10. Confirm the version displayed on the foundation footer and Alarm settings equals the APK metadata. For a CI build tagged `v0.1.0+12`, expect **0.1.0 (12)**. Debug builds add `-debug` to versionName and have a separate application ID.

The unit suite covers the fixed anchor and off weekends, weekday rota, all override categories, both UK DST transitions and gap/overlap resolution, elapsed snooze, grace/retry policy, terminal-state protection, unset pay rate, weekly totals, pay-period boundaries and overnight DST duration.
